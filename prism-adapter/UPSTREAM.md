# Prism transport source and local integration

The standalone adapter modules, browser fixtures, and regression tests are derived
from [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api), pinned to production
commit `0ae36e501952000c5c910a2e616c6e0861f66a49` (2026-10-04).

These files retain the upstream LGPL-3.0 license. See `COPYING.LESSER` and
`COPYING` in this directory. The independently implemented CLIProxyAPI Go client
communicates with this separately runnable process over its HTTP interface.
The repository's root MIT license does not replace the adapter's LGPL license.

Local changes to the imported modules:

- The state directory defaults to `/var/lib/cliproxy-prism`.
- Account keys additionally accept a 64-character hexadecimal digest generated by
  CLIProxyAPI. Upstream numeric account keys remain accepted for compatibility.
  The digest represents the CPA credential and OAuth account, not its access token.
- The client-tool smoke fixture initializes the reconnect fields introduced by
  the upstream multiplex fixture update. This is a fixture-only compatibility fix.
- Loopback browser smoke clients explicitly disable system proxy discovery;
  this avoids macOS proxy lookup blocking parallel local HTTP requests.
- Source/license notices were added. The model catalog, tool policy, cache,
  concurrency defaults, polling, runtime reconnect, and resource management are
  otherwise the upstream implementation.

The integration deliberately retains the upstream browser/turn deadlines and
bounded admission behavior as requested for sub2api parity. These settings belong
to the adapter process; the Go client does not add a network timeout. No new
conservative concurrency limits, model reductions, or deferred tool phase are
introduced by the CPA integration.

Upstream source hashes are recorded in `upstream-manifest.json`. They describe
original upstream files, before the local changes listed above.
